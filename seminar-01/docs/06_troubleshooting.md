# Диагностика без пересоздания всего стенда

| Симптом | Что проверить | Чего не делать |
|---|---|---|
| `yc` просит старый OAuth token | Версию CLI, обновление и вход через браузер | Не копировать токен в чат, env.local или metadata |
| Cloud/folder mismatch | Профиль, конкретные cloud ID и folder ID | Не менять global profile наугад и не создавать в чужом каталоге |
| Частичный сбой create | Файлы в `.state`, фактические ресурсы и операции в каталоге | Не удалять state и не повторять всю цепочку |
| Нет квоты/платформы в зоне | Доступность 4/8 standard-v3 и сетей; согласованный лимит | Не повышать ресурсы/права автоматически |
| SSH timeout | RUNNING, публичный IP, исходящий IP ноутбука/VPN, ingress /32 | Не открывать `0.0.0.0/0` для входящего SSH |
| Host key mismatch | ID ВМ и fingerprint через serial log | Не отключать host key checking |
| cloud-init failed | `sudo cloud-init status --long`, `sudo tail -n 80 /var/log/cloud-init-output.log` | Не считать созданную ВМ готовым приложением |
| Permission denied для Docker | Завершился installer? Был ли новый SSH-вход после usermod? | Не делать `chmod 666 /var/run/docker.sock` |
| Туннель: address already in use | Нет ли второго connect.sh; локальные `LOCAL_*_PORT` | Не менять порты контейнеров и не выставлять UI наружу |
| `.env` placeholders остались | `cp env.example .env`, затем configure.py, корректная папка lab | Не вставлять cloud token как LAB_ADMIN_TOKEN |
| Grafana не принимает новый пароль из .env | Пользователь уже создан в persistent volume | Не удалять volume с данными без решения; использовать штатный reset |
| k6 не нашёл API | `app` — DNS сервиса внутри Compose, не localhost ноутбука | Не подставлять публичный IP чужого сервиса |
| Lock остался | Есть ли реальный запущенный k6: `docker compose --profile load ps -a` | Не удалять lock, пока нагрузка идёт |
| No data | Targets, route/status/job, два scrape, достаточное окно и трафик | Не выдавать NaN за ноль или 100% |
| `node` DOWN | На Linux запущен ли host profile; на Docker Desktop это отдельное ограничение | Не считать отсутствие host exporter поломкой API |
| Normal имеет dropped | CPU/RAM ВМ и k6, VUS, второй тест, фоновые процессы | Не объявлять недоданную нагрузку запасом мощности |
| p99 отличается от k6 | Фильтр успешных, разные таймеры/окна, интерполяция buckets | Не подгонять buckets под ожидаемую картинку без анализа |
| После recovery ещё ошибки | Незавершённые запросы и минутное окно | Не перезапускать сервис ради очистки графика |
| `collect.sh` даёт пустое значение | Был ли трафик в выбранной исторической точке и сохранились ли данные Prometheus | Не использовать current value как будто оно измерено под нагрузкой |
| Образ недоступен | Registry/DNS и закреплённый tag | Не заменять на latest без записи версии и повторной проверки |

## Вторая попытка после прерванного облачного create

Локальные JSON пишутся после каждой команды. Пустой файл может означать, что команда оборвалась: ресурс при этом мог успеть создаться. Сначала найдите его в том же каталоге по точному имени и label; сопоставьте с операцией, затем сохраните подтверждённый ID. Не принимайте совпадение одного имени за разрешение на удаление. При сомнении остановитесь и разберите состояние с владельцем облака.

`cleanup.sh` намеренно останавливается при непроверенном результате `get`; ошибка авторизации/сети не равна NotFound. После ручного удаления части ресурсов подтвердите их отсутствие по API и только затем обновляйте state. Проверка cleanup принадлежит той же воспроизводимой процедуре, что и создание.
