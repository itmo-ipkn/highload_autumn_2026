# hw-1: золотые сигналы в Grafana

CRUD-микросервис на Spring Boot отдаёт метрики latency, traffic и errors в формате Prometheus. Генератор по списку ручек приложения строит дашборд в Grafana, а k6 создаёт фоновую нагрузку.

## Запуск

```bash
cp .env.example .env
docker compose up
```

Дашборд: http://localhost:3000/d/hw1-golden-signals (логин и пароль Grafana — из `.env`). Данные появляются через 1–2 минуты после старта контейнеров; первая сборка образов занимает ещё несколько минут.

## Сервисы и порты

| Сервис | Порт на хосте | Что делает |
|---|---|---|
| `app-dc1` | 8081 | Приложение, `POD_ID=pod-1`, `DATACENTER=dc-1` |
| `app-dc2` | 8082 | Тот же образ, `POD_ID=pod-2`, `DATACENTER=dc-2` |
| `prometheus` | 9090 | Опрашивает `/metrics` обоих инстансов раз в 5 секунд |
| `grafana` | 3000 | Datasource создаётся через provisioning с uid `prom-main` |
| `dashgen` | — | Строит дашборд и завершается |
| `load` | — | Нагрузка k6 |

Порядок запуска: приложения и Grafana проходят healthcheck → `dashgen` строит дашборд и завершается с кодом 0 → стартует `load`.

## Ручки приложения

| Ручка | Описание |
|---|---|
| `POST /items` | Создать запись, `201` |
| `GET /items/{id}` | Получить запись, `404` для несуществующего id |
| `PUT /items/{id}` | Обновить запись, `404` для несуществующего id |
| `GET /health` | `200`, когда сервис готов принимать запросы |
| `GET /metrics` | Метрики в формате Prometheus |
| `GET /handlers` | Список ручек: `[{"method": "GET", "path": "/items/{id}"}, ...]` |

## Метрики и лейблы

| Метрика | Тип | Лейблы | Для чего |
|---|---|---|---|
| `http_handler_requests_total` | counter | `method`, `path`, `status_code`, `pod_id`, `datacenter` | RPS и ошибки по кодам ответа |
| `http_handler_request_duration_seconds_bucket` | histogram | `method`, `path`, `le`, `pod_id`, `datacenter` | Перцентили p50, p95, p99 |
| `http_handler_request_duration_seconds_count`, `_sum` | histogram | `method`, `path`, `pod_id`, `datacenter` | Число и суммарная длительность запросов |

- `path` — шаблон маршрута (`/items/{id}`), а не фактический URL. Иначе каждый id давал бы новый временной ряд.
- `status_code` есть только у счётчика. В гистограмме он умножил бы число рядов на число кодов, а перцентили считаются по всем ответам ручки.
- `pod_id` и `datacenter` берутся из переменных окружения `POD_ID` и `DATACENTER` и добавляются ко всем метрикам приложения.
- Служебные ручки `/health`, `/metrics`, `/handlers` и запросы на несуществующие URL в метрики не попадают.

Метрики собирает сервлет-фильтр (`OncePerRequestFilter`) поверх Micrometer. Он берёт шаблон маршрута, который Spring MVC кладёт в запрос при выборе обработчика, а исключение, необработанно вылетевшее из контроллера, записывает как `500`.

## Почему для latency гистограмма

Перцентили должны оставаться корректными при агрегации по нескольким инстансам. Summary считает перцентиль внутри каждого инстанса, а перцентили разных инстансов нельзя ни сложить, ни усреднить. Histogram отдаёт накопительные счётчики по корзинам (`le`). Их можно сложить по всем выбранным подам и датацентрам и только потом посчитать перцентиль:

```promql
histogram_quantile(0.95, sum by (le) (rate(http_handler_request_duration_seconds_bucket{...}[$__rate_interval])))
```

Точность ограничена шириной корзины. Корзины начинаются с 0,25 мс, потому что CRUD в памяти отвечает быстрее миллисекунды.

## Генератор дашборда (`dashgen`)

1. Запрашивает `GET /handlers` у приложения.
2. Для каждой ручки копирует шаблон `handler-panels.json` (строка и три панели: Latency, RPS, Errors), подставляя метод и путь.
3. Сохраняет дашборд через `POST /api/dashboards/db` с учётными данными администратора из переменных окружения.

Список ручек в генераторе не прописан: новая ручка появится на дашборде после перезапуска стека. На дашборде есть селекторы датацентра и пода (несколько значений или All); редактировать его нельзя.

## Нагрузка (`load`)

- k6 за 3 минуты наращивает нагрузку до 30 RPS суммарно на оба инстанса и держит её, пока стек не остановят.
- Запросы распределены так: 20% `POST`, 50% `GET`, 30% `PUT`, каждый на случайный инстанс.
- Ошибки двух видов: 3% `GET`/`PUT` идут на несуществующий id (`404`), а приложение с вероятностью `FAULT_PROBABILITY` отвечает `500`.

## Переменные окружения (`.env`)

| Переменная | Назначение |
|---|---|
| `GRAFANA_ADMIN_USER`, `GRAFANA_ADMIN_PASSWORD` | Администратор Grafana; ими же пользуется `dashgen` |
| `FAULT_PROBABILITY` | Доля запросов к `/items`, на которые приложение отвечает `500` (по умолчанию `0.03`) |
