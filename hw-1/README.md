# Каталог товаров — первый этап ДЗ №1

TypeScript + Fastify, один процесс, независимое хранилище в памяти. После перезапуска все товары теряются. Этот этап содержит только API и контейнерный запуск.

## Docker Compose

Из каталога `hw-1/`, при запущенном Docker Desktop / Docker Engine:

```bash
cp .env.example .env
docker compose up
```

Node.js на хосте не требуется. Первый запуск собирает образ и загружает зависимости. API: http://127.0.0.1:8080, готовность: http://127.0.0.1:8080/health. Порт можно изменить через `API_PORT` в `.env`; внутри контейнера используется 3000. `.env` не хранится в git, секреты на этом этапе не требуются.

```bash
docker compose ps
docker compose down
# После изменения исходников:
docker compose up --build
```

## API

Товар: `{ "id": "UUID", "name": "Клавиатура", "price": 450000 }`. Цена — целое число копеек (450000 = 4500 ₽), от 0 до 9007199254740991. Имя — 1–200 символов после trim. POST и PUT требуют оба поля name и price. Строковые числа, неизвестные поля и клиентский id отклоняются. PUT полностью заменяет name и price, не создавая отсутствующий товар.

| Запрос | Ответ |
|---|---|
| POST /items | 201, созданный товар |
| GET /items/{id} | 200, товар; 404, если отсутствует |
| PUT /items/{id} | 200, обновлённый товар; 404, если отсутствует |
| GET /health | 200, `{"status":"ok"}` |

Невалидное JSON-тело и нарушения схемы дают 400 без изменения хранилища. Ошибки содержат JSON-поле `message`. Неподдерживаемый Content-Type даёт 415.

```bash
curl -i -X POST http://127.0.0.1:8080/items \
  -H 'Content-Type: application/json' \
  -d '{"name":"Клавиатура","price":450000}'

# Подставьте id из ответа POST:
curl -i http://127.0.0.1:8080/items/ID
curl -i -X PUT http://127.0.0.1:8080/items/ID \
  -H 'Content-Type: application/json' \
  -d '{"name":"Мышь","price":150000}'
curl -i http://127.0.0.1:8080/items/missing
```

## Разработка и тесты

Node.js 24.21.0 (`nvm use` при установленном nvm) и pnpm 10.19.0. Версия pnpm закреплена в `package.json` и Dockerfile. Если pnpm ещё не установлен: `npm install --global pnpm@10.19.0`. Docker устанавливает его самостоятельно. Из `hw-1/`:

```bash
pnpm install --frozen-lockfile
pnpm run build
pnpm test
POD_ID=pod-1 DATACENTER=dc-1 pnpm start
```

Локальный процесс слушает порт 3000; переменная `PORT` переопределяет его. Остановка — Ctrl+C. Для перезапуска при изменении исходников:

```bash
POD_ID=pod-1 DATACENTER=dc-1 pnpm run dev
```

Четыре небольших HTTP-теста используют Fastify inject без открытого порта: жизненный цикл товара и 404, сбор Counter/Histogram, учёт ошибок 400/404/500, каталог /handlers и исключение служебных запросов из бизнес-метрик.

## Структура

- `src/app.ts` — сборка приложения, отдельный `/health`.
- `src/server.ts` — запуск и завершение процесса.
- `src/products.ts` — бизнес-ручки и схема запросов.
- `src/store.ts` — модель и Map-хранилище.
- `src/monitoring.ts` — реестр метрик, hooks, обнаружение ручек и экспорт.
- `tests/` — HTTP-проверки.

Память растёт с числом созданных товаров; автоматического удаления нет. Длительную нагрузку и её ограничения добавим отдельным этапом.

## Мониторинг

`POD_ID` и `DATACENTER` обязательны: отсутствие или значение из пробелов завершает запуск до открытия порта. Compose передаёт их из `.env`; при обновлении старого `.env` добавьте `POD_ID=pod-1` и `DATACENTER=dc-1`, сохранив свой `API_PORT`.

| Метрика | Тип | Лейблы |
|---|---|---|
| `http_requests_total` | Counter | `method`, `route`, `pod_id`, `datacenter`, `status_code` |
| `http_request_duration_seconds` | Histogram | `method`, `route`, `pod_id`, `datacenter` |

Counter считает завершённые бизнес-ответы, включая 400, 404 и 500. Из него впоследствии вычисляются RPS и ошибки по кодам. Histogram содержит длительности в секундах; код ответа исключён ради меньшего числа рядов. `route` — шаблон `/items/:id`, без конкретных ID и query string. GET и PUT различаются `method`.

Бакеты Histogram: `0.001, 0.0025, 0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1, 2.5, +Inf` секунды. Бакеты накопительные: запрос 30 мс учитывается в 50 мс и всех больших границах. Одинаковые бакеты нескольких экземпляров можно сложить до расчёта p50/p95/p99. Готовые квантили Summary усреднять между репликами нельзя. Перцентили Histogram остаются оценкой с погрешностью внутри бакета.

Время измеряется монотонными часами от `onRequest` до `onResponse` после события `finish`, включая чтение тела, валидацию и отправку ответа сервером. Это серверная длительность, а не RTT клиента. Оборванные до завершения отправки ответы, неизвестные URL и служебные `/health`, `/metrics`, `/handlers` исключаются. 404 отсутствующего товара на зарегистрированной ручке учитывается.

```bash
curl http://127.0.0.1:8080/metrics
curl http://127.0.0.1:8080/handlers
```

`/metrics` возвращает Prometheus text format с соответствующим Content-Type; до первых запросов серии могут отсутствовать. `/handlers` возвращает:

```json
{"handlers":[{"method":"GET","path":"/items/:id"},{"method":"POST","path":"/items"},{"method":"PUT","path":"/items/:id"}]}
```

Для добавления бизнес-ручек регистрируйте их в бизнес-плагине, передаваемом в `createApp(identity, { businessRoutes })` (по умолчанию `productRoutes`). Hooks и каталог наследуются вложенными роутерами, включая префиксы. Ручные инкременты в обработчиках не нужны. Каждое приложение имеет свой реестр; служебные маршруты регистрируются вне бизнес-области.
