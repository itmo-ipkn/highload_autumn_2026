## Реализация

### 1. Приложение
- Java 21, Spring Boot 3.5.16.
- Два независимых экземпляра приложения с собственным хранилищем в памяти.
- Три CRUD-операции: POST /items, GET /items/{id}, PUT /items/{id}.
- Служебные маршруты /health, /metrics и /handlers.

### 2. Мониторинг
- Сбор HTTP-метрик через Micrometer.
- Измерение задержек, интенсивности запросов (RPS) и ошибок HTTP 4xx/5xx.
- Prometheus собирает метрики обоих экземпляров каждые 5 секунд.
- Метки pod и dc позволяют разделять показатели экземпляров.

### 3. Автоматизация Grafana
- Отдельный Python-генератор получает список маршрутов через GET /handlers.
- Дашборд создаётся автоматически через Grafana HTTP API.
- Для трёх бизнес-операций создаются 9 панелей.
- Отображаются p50/p95/p99, RPS и ошибки 4xx/5xx.
- Реализована фильтрация по pod и dc.
- Служебные маршруты исключаются из бизнес-метрик.

### 4. Генерация нагрузки
- Отдельный Python-процесс создаёт фоновую нагрузку.
- Интенсивность увеличивается от 3 до 40 RPS за 120 секунд.
- Нагрузка распределяется между двумя экземплярами.
- 4% запросов намеренно вызывают ответы HTTP 404 и 500.

### 5. Запуск и тестирование

Весь стенд запускается одной командой:

    docker compose up --build -d

Проверка всех этапов:

    bash check-stage4.sh

Результаты:

- Успешное прохождение проверок этапов 1–4.
- Оба экземпляра доступны для Prometheus.
- Дашборд Grafana генерируется автоматически.
- Фоновая нагрузка и отображение метрик работают.
