# Инструменты автоматизации в Grafana

Микросервис на Spring Boot (Java 21, Spring Data JPA, H2 in-memory) с метриками Prometheus

## Запуск

```bash
docker compose up --build
```
|            |                               |
|------------|-------------------------------|
| Приложение | http://localhost:8080         |
| Метрики    | http://localhost:8080/metrics |
| Prometheus | http://localhost:9090         |

`POD_ID` и `DATACENTER` передаются переменными окружения в docker-compose.yaml

API методы по ТЗ.

## Часть 1

### Метрики и лейблы

Идиоматичный для Spring способ: Spring Boot Actuator + Micrometer.
Служебные `/health` и `/metrics` исключены с помощью `MeterFilter`.

Основная метрика: **`http_server_requests_seconds`**, тип Histogram 
(серии `_bucket`, `_count`, `_sum`).

| Лейбл        | Значение                                        |
|--------------|-------------------------------------------------|
| `pod_id`     | номер пода, из переменной окружения `POD_ID`    |
| `datacenter` | датацентр, из переменной окружения `DATACENTER` |
| `method`     | HTTP-метод                                      |
| `uri`        | шаблон пути (`/items`, `/items/{id}`)           |
| `status`     | точный код ответа (200, 404  или другие)        |

### Почему Histogram

Перцентили должны оставаться корректными при агрегации по нескольким экземплярам.

- **Summary** считает квантили внутри приложения. Готовые квантили разных
  экземпляров нельзя ни усреднить, ни сложить: p99 от p99 не равен p99 всего
  трафика.
- **Histogram** хранит только счётчики попаданий в бакеты. Счётчики аддитивны:
  их суммируют по всем экземплярам (`sum by (le) (...)`), а затем считают
  квантиль по суммарному распределению (`histogram_quantile`). Результат
  корректен для любого числа подов.

Минус: точность перцентиля ограничена шириной бакетов (значение
интерполируется внутри бакета). Он смягчён включённой
`percentiles-histogram`, которая даёт частые бакеты от 1 мс до 30 с.

Throughput и Errors берутся из `_count` (счётчик внутри гистограммы),
поэтому отдельные метрики не нужны.
